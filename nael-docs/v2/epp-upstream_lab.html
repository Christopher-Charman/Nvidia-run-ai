Benchmarking EPP routing modes on real GPUs, real model

Two guides. 001 Setup stands the environment up once. 002 Run puts the hotspot workload on top of it and compares three EPP modes with one set of numbers.

  doc 001 (once)                                   doc 002 (per run)
  ────────────────────────────────                 ─────────────────────────────────────────
  4 GPUs → 4 vLLM pods, real model                 GuideLLM: shared 1024-token prefix,
  kgateway + InferencePool                          concurrency sweep 8 … 96, 3 repetitions
  EPP image from adaptive-with-pressure            switch EPP mode → settle 60 s → sweep
  Prometheus: EPP + vLLM                           export GuideLLM JSON + PromQL ranges

Setup is shared; only the EPP mode changes between runs.

A · static

Fixed weights, prefix 2 · KV 1 · queue 1. The baseline everyone has.

✅ runs today

B · continuous

Background configurator on; weights follow the imbalance and pressure signals.

✅ runs today

C · discrete

Predefined profiles, rules on cv and P with enter/exit bounds.

🔜 needs the prototype

What "better" will mean here: on a shared-prefix hotspot workload, C reaches the same TTFT p99 and throughput as B, with a small number of profile switches per minute and a human-readable reason for each. If the numbers do not say that, the result is the result.
